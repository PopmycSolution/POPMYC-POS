# POPMYC POS — Auto-Update Release Structure

## Update server URL

Configure in `desktop/package.json` → `build.publish.url`:
```json
"publish": {
  "provider": "generic",
  "url": "https://releases.popmycsolutions.com/popmyc-pos/",
  "channel": "latest"
}
```

Or override at build time / runtime via `POPMYC_UPDATE_URL` environment variable.

## Files required on the update server

For each release, upload these files to the update server URL:

```
https://releases.popmycsolutions.com/popmyc-pos/
├── latest.yml                          ← required: update metadata (auto-generated by electron-builder)
├── POPMYC-POS-Setup-1.0.1.exe         ← the installer
└── POPMYC-POS-Setup-1.0.1.exe.blockmap ← binary diff for delta updates
```

`electron-builder` generates all these automatically when you run:
```powershell
.\scripts\build-desktop.ps1 -Package
# Output in desktop/dist-installer/
```

## `latest.yml` format (auto-generated)

```yaml
version: 1.0.1
files:
  - url: POPMYC-POS-Setup-1.0.1.exe
    sha512: <hash>
    size: <bytes>
path: POPMYC-POS-Setup-1.0.1.exe
sha512: <hash>
releaseDate: '2026-01-15T10:00:00.000Z'
```

## Version bumping procedure

1. Update `"version"` in `desktop/package.json`
2. Update `#define AppVersion` in `desktop/installer/popmyc-setup.iss`
3. Run `.\scripts\build-desktop.ps1 -Package`
4. Upload `desktop/dist-installer/` contents to the update server
5. The existing installed app will detect and offer the update within 10 seconds of next launch

## What updates preserve

Updates NEVER touch:
- `%APPDATA%\POPMYC POS\.env` (database credentials)
- `%APPDATA%\POPMYC POS\media\` (uploaded files)
- `%APPDATA%\POPMYC POS\backups\` (database backups)
- `%APPDATA%\POPMYC POS\logs\` (log files)
- The PostgreSQL database itself

Updates DO replace:
- All application files in the install directory
- The bundled Python runtime
- The built React SPA
- The Django backend code

## Offline behavior

If the update server is unreachable (no internet, server down, wrong URL):
- `electron-updater` emits an `error` event
- `main.js` catches it silently and sets `updateState = 'error'`
- The POS continues operating normally — the update check is entirely non-blocking
- No error dialog is shown to the customer for a failed update check
